# 代表16問 人手レビュー計画

## 1. 目的と範囲

この計画は、Draft PR #5 の代表16問を、人による教材レビューと実機テストへ渡すための手順である。新機能追加、残り64問の新形式化、Phase 6の開始、公開Pagesへの反映は対象外とする。

レビュー結果の作業用正本は [`public/review-checklist.csv`](../public/review-checklist.csv) とする。問題本文の配信データは `public/questions-alpha-80.json` が正本であり、CSVだけを直して問題データを変更した扱いにはしない。レビューで修正が必要になった場合は、CSVへ指摘を記録した後、別の修正差分でJSONと生成物を同期する。

公式PDFはGitへ追加しない。出典本文を確認する担当者は、指定版PDFをローカルだけに置き、リポジトリ外の `SSW2_SOURCE_DIR` から参照する。

## 2. 開始時の状態

- 対象は `schemaVersion=0.4.0` の16問だけである。
- 16問とも `status=source_checked`、`user_approval=pending` である。
- `current_reviewer_type=ai_source_review` は既存の出典照合記録を示す。人による日本語・教材性・ネイティブ翻訳確認が完了したことを意味しない。
- 16問とも、ふりがな、日本語教材性、インドネシア語ネイティブ、answer leak、実機操作の人手ゲートは開始時点でpendingである。
- 自動検査や既存の `pass` を、人による各ゲートの代用にしない。
- `q045`、`q055`、`q078`、`q079` には、選択肢の `ja` と `easyJa` の一致・相違パターンが正答位置と相関する既知課題がある。`correction_notes` の記録を起点に人が確認し、自動修正済み・answer leak確認済みとは扱わない。
  - `q045`: 正答Dの `easyJa` が原文と同じで、学習補助としての追加価値が不明である。
  - `q055`: 選択肢の `easyJa` で限定表現「だけ」が失われているものがある。
  - `q078`: 正答Dの `easyJa` で「塊」が失われている。
  - `q079`: 選択肢の `easyJa` で限定表現「だけ」が失われているものがある。

## 3. 担当の分離

最低限、次の担当を分ける。

1. 日本語確認者: 問題文、選択肢、ふりがな、やさしい日本語、日本語ポイント、教材性を確認する。
2. インドネシア語ネイティブ確認者: 全文訳、設問意図、選択肢訳、正答・不正答理由、用語統一を確認する。日本語確認者とは別の人にする。
3. answer leak確認者: 回答前のLevel 3を学習者の視点で確認する。可能なら翻訳作成者とは別の人にする。
4. 実機確認者: レビュー用artifactをスマートフォンまたは実機相当環境で操作する。

同じ人が複数の役割を持つ場合も、CSVの `correction_notes` には観点ごとの判定を分けて記録する。

## 4. 4問×4セット

セットは `public/review-checklist.csv` の `pilot_set` で絞り込む。Aから順に行い、1セットの指摘を反映・再確認してから次へ進む。

| セット | 問題ID | 主な確認対象 |
|---|---|---|
| A | `q001`, `q008`, `q035`, `q049` | 基礎知識、時期、条件付き数値、単位・希釈計算、模式図 |
| B | `q033`, `q045`, `q078`, `q080` | 否定・除外表現、測定部位の模式図、専門語、大部分を問う表現 |
| C | `q004`, `q029`, `q044`, `q057` | 原則、最初の行動、安全距離、教材に沿う利点 |
| D | `q013`, `q016`, `q055`, `q079` | 長文、交配用語、組合せ、方法を限定する表現 |

この分割はレビュー順を決めるためのもので、問題の難易度や承認状態を変更しない。

## 5. セット開始前の準備

1. PR #5のレビュー対象HEADを記録する。途中でHEADが変わった場合は、未確認差分を確認してから再開する。
2. GitHub Actionsから `temporary-pr-review-build-7d-pr-` で始まる期限付きPRレビューartifactを取得し、展開した `dist` または `standalone-review.html` を使用する。public repository上のartifactはアクセス制限ではなく、未確認翻訳を含む正式配布前の確認物である。公開Pagesは使用・更新しない。
3. artifact名、HEAD、端末名、OS、ブラウザとバージョン、画面幅、確認日をレビュー記録へ残す。
4. CSVを表計算ソフトで開き、`pilot_set` を対象セットへ、`schema_version` を `0.4.0` へ絞り込む。
5. 出典担当だけが必要な公式PDFをローカルの `SSW2_SOURCE_DIR` から開く。PDFをartifact、レビュー共有ファイル、Git差分へ含めない。
6. 学習履歴の競合を避けるため、レビュー中はアプリを一つのタブまたはウィンドウだけで開く。複数タブ対応は [Issue #6](https://github.com/0310masato/ssw2-livestock-trainer/issues/6) で追跡する。

## 6. 1問ごとのレビュー手順

### 6.1 日本語・ふりがな

- 日本語だけで、何を一つ選ぶ問題か理解できるか確認する。
- 数字、単位、時期、範囲、否定、例外、最上級、原則、手順の条件が曖昧でないか確認する。
- 問題、4選択肢、回答後解説、選択肢別理由の漢字に、文脈上正しいふりがなが付くか確認する。
- やさしい日本語が事実、条件、正答範囲を変えていないか確認する。
- 選択肢の `easyJa` は学習者向け画面へ表示せず、レビュー用データとして `ja` と並べて確認する。言い換えの有無、長さ、具体性、自然さが正答だけ異ならないか確認する。
- 実際の問題文と日本語ポイントが一致するか確認する。

### 6.2 教材性・出典

- CSVの `source_title`、`source_edition`、`pdf_page`、`printed_page`、`source_section` を指定版教材と照合する。
- 問題、正答、各理由が教材の記述範囲に収まり、教材外の推測を足していないか確認する。
- 重要語が1〜5語で、問題理解に必要な語を扱い、正答だけを示す語の組合せになっていないか確認する。
- 公式教材の文章・図・写真を大量転載していないか確認する。独自模式図は内容とaltを確認する。

### 6.3 インドネシア語ネイティブ確認

- 全文訳、設問意図、4選択肢、正答理由、4選択肢理由、重要語を確認する。
- 数字、単位、否定、例外、比較、義務・禁止、主語と対象が日本語と一致するか確認する。
- 専門語の訳を選択肢間・問題間で統一し、必要な `インドネシア語（日本語／ふりがな）` があるか確認する。
- 設問意図が「何を選ぶか」だけを示し、正解の内容を説明していないか確認する。
- 機械翻訳らしい不自然さ、意味の追加・脱落、答えを強く連想させる言い換えを記録する。

### 6.4 answer leak

Level 3で未回答のまま、問題、全文訳、設問意図、重要語、例文、4選択肢訳をすべて開いて確認する。

- 正解だけ説明が長い、具体的、自然になっていないか。
- 全文訳や設問意図に正答語・正答条件が追加されていないか。
- 重要語の語義や例文だけで正答を特定できないか。
- 不正解候補だけを消去できる訳し分けになっていないか。
- 回答前・回答後の学習者向けDOMに、選択肢の `easyJa` が含まれていないか。
- レビュー用データでは4選択肢の `ja` と `easyJa` を比較し、一致・相違、長さ、具体性、自然さの差が正答位置を識別しないか。特に `q045`、`q055`、`q078`、`q079` の既知相関を確認する。
- 回答前DOMや画面に正答理由、不正解理由、覚えるポイントが出ていないか。

### 6.5 Level 0〜3と実機操作

各セットで4レベルを最低1回ずつ確認し、問題の種類が異なるものへ割り当てる。指摘が出た表示は同じ問題・同じレベルで再確認する。

- Level 3: 回答前に全ふりがな、問題文のやさしい日本語、全文訳、選択肢訳、重要語、インドネシア語の設問意図が表示される。選択肢の `easyJa` は回答前後とも表示されない。
- Level 2: ふりがな、重要語、設問意図は表示され、全文訳はボタンで開く。やさしい日本語と選択肢訳は初期表示されない。
- Level 1: 回答前はふりがなと短い用語ヒントだけで、インドネシア語は回答後に初めて開ける。
- Level 0: 回答前は日本語問題・日本語選択肢だけ、回答後も教材内容は日本語だけである。
- 回答後に正答理由、4選択肢理由、重要語、日本語ポイント、教材名・版・ページ・章が確認できる。
- 「日本語だけでもう一度解く」でLevel 0へ移り、元回答のmasteryと復習予定が二重更新されない。
- 保存言語をインドネシア語にして模試へ入り、模試中は画面全体が日本語だけになる。模試終了後は保存済みインドネシア語へ戻る。
- 360px幅で横スクロール、文字重なり、ボタン欠けがない。
- 操作中のJavaScript console/page errorが0件である。

## 7. CSVへの記録

`public/review-checklist.csv` は80問を維持し、代表16問は `pilot_set` がA〜Dの行である。主な列の扱いは次のとおり。

| 列 | 記録内容 |
|---|---|
| `question_id`, `question_ja` | 対象問題の固定識別子と日本語問題文 |
| `source_title`, `source_edition`, `pdf_page`, `printed_page`, `source_section` | 人が照合する出典情報 |
| `content_review`〜`user_approval` | 問題JSONの現在のreview状態。CSVだけを変更してJSON更新済みとは扱わない |
| `current_reviewer_type`, `current_reviewed_at` | 現在保存されているレビュー記録の種別と日付。開始時は人手完了の証拠ではない |
| `device_review` | 実機確認の `pending` / `pass` / `fail` |
| `correction_notes` | 人手レビューの指摘、修正案、再確認結果 |

指摘は次の書式で1セルに追記する。複数観点は ` / ` で区切る。

```text
[観点][判定] 現状 -> 修正案（担当者、YYYY-MM-DD、端末または教材ページ）
```

例:

```text
[furigana][fail] 「生産」の読みを文脈確認 -> せいさんへ修正（JA-01、2026-08-20、qXXX） / [device][pass] 360px横スクロールなし（QA-01、2026-08-21、Android/Chrome）
```

ルール:

- 修正が必要なら該当ゲートを `fail` とし、曖昧なまま `pass` にしない。
- 未実施・再確認前は `pending`、ネイティブ未確認は `pending_native_review` を維持する。
- 修正後の `pass` は、修正者ではなく該当レビュー担当者が再確認して記録する。
- 問題文、出典、レビュー状態をCSVだけで直さない。配信JSONとの同期が必要な変更として切り分ける。
- レビュー用artifactで見つけた実装不具合は、問題内容の指摘と区別して `[device]` で記録する。
- 既知課題の `correction_notes` は人手ゲートの代用ではない。修正文案を人が確定するまで該当ゲートは `pending` を維持し、問題JSONの変更、生成物同期、全16問の回帰は別PRで行う。

## 8. セット完了と引き渡し

各セットは、次を満たした時だけ「人手レビュー完了候補」として次へ渡す。

- 4問すべてで日本語、ふりがな、日本語教材性、インドネシア語ネイティブ、answer leakの結果と担当記録がある。
- 実機操作4問が `device_review=pass` である。
- `fail` の修正と再確認が済み、未解決の内容は明示されている。
- `q045`、`q055`、`q078`、`q079` の既知answer leak課題について、人手判定と別PRでの修正文案・回帰計画が記録されている。
- 修正後の自動検査とレビュー用artifactのHEADが一致する。

4セットが完了しても、このPRでは問題を `approved` へ昇格しない。`user_approval=pending` を維持し、Draft解除、merge、Pages反映、残り64問の移行、Phase 6開始は別の明示的判断とする。
