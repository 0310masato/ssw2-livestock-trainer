# ふりがな作成・確認方針

関連文書: [README](../README.md) / [教材設計概要](PEDAGOGY_SPEC.md) / [学習支援レベル仕様](LEARNING_SUPPORT_SPEC.md) / [レビュー・チェックリスト](CONTENT_REVIEW_CHECKLIST.md)

## 1. 目的

ふりがなは、インドネシア人学習者が日本語問題を自力で読めるようにする学習補助である。日本語本文を別文へ置き換えず、読みだけを構造化データとして付与する。

## 2. データ形式

- `LocalizedText.rubyJa` の `RubySegment[]` を使用する。
- 漢字を含むsegmentには `reading` を付け、HTMLでは `<ruby><rt>` として表示する。
- 括弧書き、全角括弧、スラッシュで読みを本文へ埋め込まない。
- `ja` と `rubyJa[].text` を連結した文字列は、空白正規化を除き一致させる。
- 問題文、全選択肢、日本語解説、全選択肢別理由、学習目標、覚えるポイントを確認対象とする。

例:

```json
{
  "ja": "最も適切なもの",
  "rubyJa": [
    { "text": "最も", "reading": "もっとも" },
    { "text": "適切", "reading": "てきせつ" },
    { "text": "なもの" }
  ]
}
```

## 3. 付与範囲

- 原則として、学習対象テキストに現れるすべての漢字へ読みを付ける。
- 数字、単位、記号、ひらがな、カタカナ、一般的な英字略語には不要な読みを付けない。
- 熟語は、学習者が語として認識できる自然な単位にまとめる。
- 活用語は漢字部分と送り仮名を分けてもよいが、画面上で元の日本語が変わらないようにする。
- 固有名詞、品種名、専門語、複数の読みがある漢字は、問題文の意味と公式教材の用法に合う読みを人が確認する。
- 同一問題内の同一語は同じ読みを使う。共通用語集に登録された語は用語集の読みを優先する。

## 4. 読みの判断

- 一般的な辞書だけでなく、文脈、畜産用語、教材内の表記を確認する。
- 「日本」は文脈なく自動的に `にっぽん` または `にほん` へ固定しない。
- 数助詞や単位の連濁・促音（例: 1匹、8割）を、表示する場合は文脈に合わせる。
- 送り仮名をreadingへ重複して含めない。
- 機械生成したrubyはdraftであり、`review.furigana=pass` になるまで確認済みとは扱わない。

## 5. 重点表現

次の試験日本語は、読みだけでなく [問題解説方針](QUESTION_EXPLANATION_POLICY.md) の日本語ポイントでも説明する。

- 最も適切
- 誤っている
- 適切でない
- してはいけない
- 必ず
- 除く
- 原則として
- すべて選ぶ

否定・例外表現は、本文の日本語を変えずに視覚的な強調を付ける。強調対象は文型キーにより特定し、全文を警告色にしない。

## 6. レビュー手順

1. `ja` とruby segment連結の一致を自動検査する。
2. 漢字を含むのに `reading` がないsegmentを自動検出する。
3. 日本語確認者が問題文、選択肢、解説を文脈付きで読む。
4. 共通用語集との読みの不一致を確認する。
5. 360px幅で長いrubyが重なったり横にはみ出したりしないことを確認する。
6. 確認者、日付、注記を記録し、パイロットの `review.furigana` を `pass` にする。

自動検査PASSだけで `review.furigana=pass` にしてはならない。不明な読みが1件でもあれば `pending`、明確な誤りがあれば `fail` とする。

## 7. 模擬試験と支援レベル

- Level 3、2、1では仕様に従ってふりがなを利用できる。
- Level 0では表示しない。
- 模擬試験では、保存設定にかかわらず `<ruby>` と `<rt>` を生成しない。CSSで隠すだけにしない。
- ふりがなを一度でも可視にした回答は `usedFurigana=true` として保存する。
